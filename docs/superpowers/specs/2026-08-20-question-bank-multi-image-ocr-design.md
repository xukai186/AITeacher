# 题库多图 OCR 工作台 — 产品设计规格

**日期：** 2026-08-20  
**状态：** 待实现  
**依赖：** 全局题库 P1–P3、OCR 守卫与软删除、并发精确去重  
**关联：** `docs/superpowers/specs/2026-08-04-global-question-bank-design.md` §5.3、§9，`docs/superpowers/specs/2026-08-13-question-bank-ocr-guard-soft-delete-design.md`，`docs/superpowers/specs/2026-08-20-question-bank-concurrent-dedupe-design.md`

## 1. 背景与目标

当前题库 OCR 仅支持**一图一题**：

- 前端只允许上传单个图片文件
- 后端 `QuestionOCRService` prompt 写死为 “Extract this single question”
- OCR 成功后进入单题补全与确认页，再创建 1 条 `ocr_import`

这不足以覆盖老师常见的两类录题场景：

1. **一图多题**：一张卷面/截图包含多道题，老师希望一次识别后逐题删改并批量提交。
2. **多图一题**：一道题被拍成多张图（如题干与选项/答案跨页），老师希望按上传顺序合并识别。

目标：

1. 引入统一的 **OCR 工作台**，承载一图多题与多图一题两种模式。
2. 一图多题支持 **切分 → 逐题删改 → 批量智能补全 → 一次性提交**。
3. 一图多题切分失败时，不退回单题流，而是返回 **原始 OCR 文本** 供老师手动拆题。
4. 多图一题按上传顺序直接合并识别，并尽量复用现有单题 OCR / enrich / create 语义。

---

## 2. 已确认决策

| 维度 | 决策 |
|------|------|
| 实施顺序 | 先做 **一图多题**，再做 **多图一题** |
| 一图多题确认方式 | 逐题确认、逐题可删改，最后一次性批量提交 |
| 一图多题切分失败 | 返回原始 OCR 文本，用户手动拆题 |
| 多图一题合并方式 | 按上传顺序直接拼接后识别 |
| 图片来源记录 | 每道题都引用同一个原始图片资产 |
| 多图一题 `source_image_asset_id` | 记录首张图 asset id；其余图片仅参与识别 |
| 批量创建 | 前端循环调用现有单题创建接口；本期不做批量事务接口 |
| 本期不做 | 自动重排图片顺序、切片图落库、多图多题混合输入、向量语义去重 |

## 3. 产品形态

### 3.1 统一入口：OCR 工作台

现有「图片识别添加」升级为 OCR 工作台入口，但保留其在题库创建弹窗中的位置。

工作台支持两种输入模式：

1. **一图多题**
   - 上传 1 张图片
   - 后端尝试切分为多道题
2. **多图一题**
   - 上传多张图片
   - 后端按上传顺序合并识别为 1 道题

### 3.2 一图多题流程

1. 上传单张图片
2. 调用 OCR 切分接口
3. 后端返回二选一结果：
   - `segmented`：识别出 `questions[]`
   - `raw_text_fallback`：切分失败，返回 `raw_text`
4. 前端进入工作台编辑区
   - `segmented`：显示题目卡片列表
   - `raw_text_fallback`：显示原始 OCR 文本，并允许手动拆题
5. 用户可对题目逐条：
   - 编辑题型、题干、选项、答案
   - 删除不需要的题
   - 新增手工题草稿
6. 用户点击「批量智能补全」
7. 系统对保留题目逐题补全属性
8. 用户在确认态逐题修正属性
9. 点击「批量提交」后，逐题创建 `ocr_import` 题库项

### 3.3 多图一题流程

1. 上传多张图片
2. 前端按上传顺序传递 `asset_ids`
3. 后端按该顺序合并识别为 1 道题
4. 前端进入工作台，但题目列表仅有 1 题
5. 后续沿用现有单题 enrich 与创建语义

## 4. API 设计

### 4.1 图片上传

继续复用现有：

- `POST /org/question-bank/upload-image`

约束：

- 一图多题：上传 1 个 asset
- 多图一题：上传多个 asset
- 前端自行维护上传顺序

### 4.2 OCR 请求

建议扩展现有 `POST /org/question-bank/ocr`，而不是为每个模式新开独立路由。

请求示意：

```json
{
  "mode": "single_image_multi_question",
  "asset_ids": ["uuid-1"]
}
```

或：

```json
{
  "mode": "multi_image_single_question",
  "asset_ids": ["uuid-1", "uuid-2", "uuid-3"]
}
```

校验规则：

- `single_image_multi_question`：必须恰好 1 个 `asset_id`
- `multi_image_single_question`：至少 2 个 `asset_id`
- 所有 asset 必须属于 `actor.org_id`

### 4.3 OCR 响应

建议引入判别式响应：

#### 一图多题成功

```json
{
  "mode": "segmented",
  "questions": [
    {
      "q_type": "single_choice",
      "stem": "…",
      "choices": [{"key": "A", "text": "…"}],
      "answer_key": "A"
    }
  ]
}
```

#### 一图多题切分失败

```json
{
  "mode": "raw_text_fallback",
  "raw_text": "…"
}
```

#### 多图一题成功

```json
{
  "mode": "single_question",
  "question": {
    "q_type": "single_choice",
    "stem": "…",
    "choices": [{"key": "A", "text": "…"}],
    "answer_key": "A"
  }
}
```

### 4.4 Enrich 与创建

- **不改**现有 enrich 接口的核心语义
- OCR 结果中的每道题仍独立调用 enrich
- 批量提交时，前端逐题调用现有 create 接口

这样可以直接复用现有：

- `ocr_import` 守卫
- 精确去重 / 并发去重
- 审核状态流转
- 现有错误文案与 API 行为

## 5. 数据模型与来源追踪

### 5.1 题目级图片来源

本期不新增题目切片资产。

每道题的 `source_image_asset_id` 规则如下：

- **一图多题**：该批所有题都指向同一个原始图片 asset
- **多图一题**：该题指向首张图 asset

其余图片仅参与 OCR 输入，不落到 `question_bank_items` 字段中。

### 5.2 不新增字段

本期不增加以下字段：

- `source_image_asset_ids`
- `ocr_batch_id`
- `ocr_segment_index`
- 题目切片图存储字段

原因：

- 现有题库创建与审计链路以单个 `source_image_asset_id` 为中心
- 本期目标是先打通老师录题效率，而不是做完备的 OCR 资产建模

## 6. 前端工作台行为

### 6.1 列表编辑区

一图多题成功后，前端展示题目草稿列表。每个草稿支持：

- 编辑 `q_type`
- 编辑 `stem`
- 编辑 `choices`
- 编辑 `answer_key`
- 删除该题

并支持：

- 新增空白草稿
- 调整题目显示顺序（可选；本期可不做拖拽，仅按列表顺序展示）

### 6.2 原始文本降级区

当后端返回 `raw_text_fallback` 时，展示：

- 原始 OCR 文本只读/可复制区域
- 「新增题目」按钮
- 每个手工草稿的编辑卡片

此模式下不自动生成 `questions[]`，由老师手动拆题后继续补全与提交。

### 6.3 批量补全

用户点击「批量智能补全」后：

- 对当前保留题目逐题调用 enrich
- 成功项写回属性建议
- 失败项保留原题面并标记错误

失败项支持：

- 单题重试
- 手动填写属性后继续提交

### 6.4 批量提交

用户点击「批量提交」后：

- 前端逐题调用 create
- 成功项标记为已提交
- 失败项保留在工作台，显示错误原因

典型失败包括：

- 409 精确重复
- 422 数据不合法
- 5xx 模型或服务错误

不要求整批全成或全败。

## 7. 后端 OCR 识别策略

### 7.1 一图多题

`QuestionOCRService` 需新增一图多题模式，要求模型返回：

- 成功：结构化 `questions[]`
- 失败：原始文本 `raw_text`

推荐 prompt 语义：

1. 先判断图片中是否存在多道独立题目
2. 若可稳定切分，输出严格 JSON 数组
3. 若无法稳定切分，不要伪造题目，改输出原始识别文本

### 7.2 多图一题

服务按上传顺序读取多张图片，作为同一条消息内容的一组图片输入模型。

推荐 prompt 语义：

1. 这些图片共同描述同一道题
2. 按输入顺序拼接上下文
3. 输出 1 个结构化题目对象

### 7.3 错误语义

沿用现有约定：

- asset 不存在 / 不属于当前机构 → 404
- 模型策略未配置 → 503
- 模型响应不可解析 / OCR 失败 → 502

---

## 8. 兼容与迁移

### 8.1 与现有单题 OCR 的兼容

- 现有单题 OCR 不移除
- OCR 工作台可兼容单题模式
- 多图一题在工作台内表现为“仅 1 题的结果列表”

### 8.2 实施顺序

建议分两步：

1. **Phase A：一图多题**
   - 工作台结果列表
   - `segmented` / `raw_text_fallback`
   - 批量 enrich / 批量提交
2. **Phase B：多图一题**
   - 多图上传
   - 按顺序合并识别
   - 单题结果接入同一工作台

---

## 9. 明确不在本期范围

- 自动裁切并保存题目级图片切片
- 多图多题混合输入
- 自动判断多图顺序
- 后端批量创建事务接口
- 向量语义去重
- OCR 结果直接跳过人工确认

---

## 10. 成功标准

1. 一张包含多道题的图片可被切分为题目列表，并支持逐题删改后批量提交。
2. 切分失败时，老师可基于原始 OCR 文本手动拆题完成入库。
3. 多张图可按上传顺序合并识别为一道题。
4. 整个流程复用现有 enrich / create / 审核 / 去重语义，不破坏现有单题 OCR。
